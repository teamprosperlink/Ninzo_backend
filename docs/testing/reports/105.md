# Test report: hubs, restock data and the hub simulator (#105)

- Date: 2026-11-10

## Scope
v0.7.0 part A. Migration 0025: `hubs`, lots waiting at a hub, `restock_requests`, `restock_lines`, `restock_lots` and `shortfalls`. `getRestockOptions`, `getRestock`, and `restock_request` in `getRiderState`. A hub simulator standing in for hub staff until v0.8.0. A `hubs` step in the test data tool. A scan of a lot still at a hub is refused unless the lot is in the rider's own packed cassette.

**Not covered here:** suggestions (part B), manual requests, shortfall answers and the pickup flow (part C).

All passed locally. Three tests first failed with "tuple concurrently updated" while making their test databases, because two suites ran at once; each passed when run again alone.

## Scenarios
| Rule | Tested |
|---|---|
| The simulator moves a confirmed request to hub_accepted, packing and ready on time, one state per step, telling the rider each time | Yes |
| Whole lots, earliest expiry first; expired, quarantined, scooter-held and already-packed lots are never packed; a released lot can be packed again | Yes |
| A short fill offers another hub only if it holds enough, else a partial fill | Yes |
| One open request per scooter; two requests never share a lot | Yes |
| Options: active hubs in the rider's zone and items on sale; another rider's request is 404; a blocked rider is refused | Yes |
| The request in progress shows in the rider's state; a closed one does not | Yes |
| A lot at a hub is scanned only from the rider's own packed cassette, and then leaves the hub | Yes |
| The test hubs step adds a hub and lots per test zone once | Yes |

**Deliberate breaks:** 20. 16 caught after two tests were added and two invalid breaks were redone. Not caught: the order of the simulator's steps (the timestamp each step sets already prevents two moves in one pass, so this is not a defect); and two concurrency breaks (packing with SKIP LOCKED, and without the hub lock), because the concurrent packing test does not reproduce the race reliably. The fix for that race is by construction: packing takes the hub's row lock first. Untested: a request that fails every time is skipped, because forcing a failure needs a trigger the test role cannot create.
