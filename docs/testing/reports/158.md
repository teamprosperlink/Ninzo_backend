# Test report: #158, the rider app's fields

Date: 2026-11-11. Local Postgres only. Migration 0039 is not on Supabase.

## What was built (from the rider app developer's feedback, #154)
- Rider: `created_at`, `approved_at` (the newest approval in the audit trail, null before).
- Shift: `node_assigned_at` (the shift start, or when the rider accepted the last move in the shift, since the node changes at accept) and `scooter {id, plate, battery_pct}` (battery null until scooter data).
- Node: `hub_distance_m`, straight line to the nearest active hub in the node's zone, null with none.
- `order_number`, a readable letter and four digits such as A2931, on the rider's offer and order and the customer's order (migration 0039 numbers orders).
- Relocation suggestion: `orders_waiting` (migration 0039 keeps the count; null for older moves).
- Restock: `ready_in_s` from the hub's slot; hub `lat`, `lng` everywhere; the other hub's `distance_m` on a shortfall, from the rider's node.
- Stock: `image_url`, the item's photo.
- Reasons per document (point 22) need document storage and move to #159.
