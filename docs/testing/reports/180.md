- Date: 2026-11-12
- Commit SHA: see PR
- Branch: `feat/180-routing-client`
- Environment: Windows 11 (arm64), Go 1.27.3, Task 3.54.0. No database and no OSRM server: the tests use a fake OSRM (`httptest`) that answers like OSRM's HTTP API v5.
- Tester / reviewer: Claude (geo session); independent review by a separate Claude agent

## 1. Scope
New package `internal/routing` (geo record W1 step 5): `Route`, `Table` (many sources to one destination) and `Nearest` against OSRM. Every answer carries `Source` (`osrm` or `placeholder`). No caller uses it yet (matching is W5). `env.example`: `ROUTING_ENGINE_URL` (already listed) gets a real comment, plus `ROUTING_PROFILE`.

Behaviour:
- No URL, a failure (network, timeout, HTTP error, a reply that is not proper OSRM JSON, a missing, negative or non-finite number, wrong row counts): straight line at the caller's speed, `Source: placeholder`.
- `NoRoute`, a null `/table` cell, or `NoSegment` (no road near a coordinate): unreachable, from OSRM, never a straight line. A table answering `NoSegment` asks for the destination alone (no road there: every source unreachable), then splits the sources in halves to find the ones with no road.
- Other HTTP 400 codes (`InvalidQuery` and so on): a bug on our side, so it falls back and counts in `Stats.Refused`, without tripping the breaker.
- One timeout (default 300 ms) covers a whole call, however many `/table` requests it needs. Tables split to OSRM's rule (sources × destinations ≤ `--max-table-size`²), at most 500 coordinates per URL.
- Circuit breaker: 3 failures in a row open it for 10 s; after that exactly one call probes. A caller that gives up (its own context) frees the probe and counts nothing.

## 3. Deliberate breaks
Each change was made alone, the suite run, the code restored (`cmp` confirmed), and the suite passed again.

| Break | Caught by |
|---|---|
| No chunking of large tables | `routing_test.go: chunk sizes [12], want [5 5 4]` |
| A null table cell becomes a straight line | `TestNoRoadIsUnreachableNotAStraightLine` |
| The probe slot never freed after a cancelled caller | `after a cancelled probe the next call must probe again` |
| `geometries=geojson` dropped (OSRM would send a polyline) | `TestRouteFromOSRM` and the breaker test |
| `annotations=duration,distance` dropped (no distances) | `TestTableKeepsOrderAndSplitsLargeRequests` |
| The single-probe rule dropped | `10 requests reached OSRM while half-open, want exactly 1` |
| An opening counted on every failure | `BreakerOpens:18, want 20 failures and one opening` |
| `NoSegment` treated as a refusal | `route ... Source:placeholder, want unreachable from OSRM` |
| A refusal counted as a failure | `1 requests, want 3: a refusal must not open the breaker` |
| A timeout per request instead of per call | `TestOneTimeoutCoversAWholeTable` |
| `NoSegment`: no destination check first, one source at a time | `399 requests, want 2: the table, then the destination alone` |
| `MaxTable` squared without a cap (overflow) | `perSource 1` for `MaxTable: math.MaxInt` |

## 4. Independent review
First pass: FAIL, with four findings: tests did not pin the query parameters or the single probe; `BreakerOpens` over-counted (18 for one opening); request errors (`NoSegment`, `InvalidQuery`) tripped the breaker and gave a straight line; the table split was far stricter than OSRM's real rule, with a timeout per chunk. All four fixed as above, and the reviewer's mutations added to the breaks. Second pass: PASS, with three points that do not block: a table answering `NoSegment` re-asked one source at a time (now: the destination alone first, then halves; tested), `MaxTable` overflow when squared (now capped; tested), and URL length unverified on a real server (W1b checks a 500-coordinate table against real OSRM).

## 5. Known limits
- Tested against a fake that follows OSRM's documented API, not a real OSRM. The real server and golden Bengaluru routes come in W1b.
- A `Table` falls back as a whole if any chunk fails, so one answer never mixes sources.
