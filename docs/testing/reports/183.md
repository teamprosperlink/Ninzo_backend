- Tester / reviewer: Claude (geo session); independent review by a separate Claude agent

## 1. Scope
- **`tools/osrm/build.sh`** has three modes:
  - `bengaluru` downloads Geofabrik's southern zone (533 MB) and checks it against Geofabrik's MD5. It resumes a stopped download only for the same file. It then clips to 77.35,12.75 to 77.90,13.25 and builds OSRM with MLD.
  - `test` builds the committed test-zone extract.
  - `testdata` re-cuts that extract and its signal list.
  
  Each build writes `build.json` with the source URL and sha256, the clip box, the extract's sha256 and OpenStreetMap timestamp, the profile version and sha256, the OSRM image digest, the osmium version and the build time. On Linux the containers run as the current user.
- **`tools/osrm/osmium.Dockerfile`** installs osmium-tool 1.15.0-1 on a debian base pinned by digest.
- **`tools/osrm/profiles/scooter.lua`**, version scooter-2, is a thin layer over OSRM's `car.lua`:
  - left-hand driving
  - a speed table per road type that a `maxspeed` tag can lower but never raise, plus a 40 km/h cap
  - 30 s per signal, a 60 s U-turn, and a harder turn across traffic
  - two-wheeler access and restriction tags first
  - no motorways unless tagged `motorcycle=yes`
  
  All the numbers are placeholders until the road test.
- **`tools/osrm/testdata/`** holds `test-zones.osm.pbf` (4.3 MB, © OpenStreetMap contributors, ODbL), `signals.txt` (344 nodes) and a `README.md` with the credit and licence. `.gitattributes` marks `*.pbf` as binary.
- **`deploy/compose.geo.yml`** gains an `osrm` service on 127.0.0.1:5001, only under the `osrm` compose profile, so `task geo:db:up` does not start it.
- **New tasks:**
  - `geo:osrm:build` stops OSRM first.
  - `geo:osrm:up` waits until a route answers, because the image has no curl or wget for a compose healthcheck.
  - `geo:osrm:down`
  - `geo:test:routes`
- **`internal/routing/golden_test.go`** runs only with `ROUTING_TEST_URL` set, and fails instead of skipping when `REQUIRE_ROUTING_TESTS=yes`.

How the fixtures were chosen. Scratch programs did the picking, and the chosen points are frozen in the test:
- **One-ways:** all 43 one-way residential, tertiary and secondary streets of at least 200 m inside one test zone were routed both ways. Against was 3.4 to 20 times longer every time. 11 were kept.
- **Signals:** for each signal on 8 long main-road routes, a route from 70 m before to 70 m after it. 10 straight crossings were kept. Each shows exactly 30.0 s of junction cost (the route's time minus its segment times).
- **Closed streets:** the `motor_vehicle=no` residential streets in the test box, routed end to end. 4 were kept, with detours of 1.6 to 20 times.

## 3. Deliberate breaks
Each break changed the profile alone. The test data was rebuilt, OSRM restarted, and the goldens run; then the profile was restored (checked with `cmp`) and the goldens passed again.

| Break | Caught by |
|---|---|
| `oneway_handling = false` | `against the one-way: 128 m, 16 s; with it: 128 m, 16 s; want at least twice as long` |
| Signal wait 8 s | `8.0 s of junction cost crossing 1 signal nodes straight, want about 30 s` |
| Signal wait 2 s (car.lua's default; first version) | `route 0: 33 s of junction cost for 10 signal nodes, want at least 120 s` |
| `motor_vehicle` dropped from the access tags | `the route uses the closed street (node 3870651468)` |
| No ceiling: `maxspeed` decides | `route 3 segment 21: 47.7 km/h, over the 40 km/h cap` |
| No speed cap, car speeds (first version) | `route 0 segment 0: 54.0 km/h, over the 40 km/h cap` |

## 4. Independent review
- **First pass:** PASS, with fixes recommended before the PR. All of them are fixed except the motorway exclusion, which is recorded as a known limit (section 5):
  1. A `maxspeed` tag raised speeds above the table. The table is now a ceiling.
  2. The cap test sat at the edge of rounding. It now skips segments under 60 m, with 3% tolerance.
  3. The signal test mixed signal waits with turn costs, so it caught 2 s but not, say, 8 s. It now uses straight crossings and catches 8 s.
  4. Node ids lost precision at 10 digits. This is now commented, and closed streets compare exact ids.
  5. `build.sh` lacked download verification, provenance, pins and a non-root user. All are added.
  6. The restriction list used the car's modes. It now puts the two-wheeler tags first.
  7. There was no refused-road golden and no healthcheck. The closed-street golden and the readiness wait are added.
  8. A licence note and `.gitattributes` were missing. Both are added.
- **Second pass:** PASS. Its three small notes are fixed: the compose file now pins the OSRM image by digest too; a Bengaluru rebuild reuses the file on disk before fetching the MD5, so it works offline; and the osmium image is tagged with its Dockerfile's hash, so any change builds a new one.

## 5. Known limits
- Every profile number is a placeholder until the road test (W8). The goldens check the profile's behaviour, not that its numbers are right.
- Not yet covered by a golden route:
  - U-turns
  - right turns across traffic
  - the per-road-type ceiling (OSRM's annotations do not name the road type; the 40 km/h cap is checked)
  - the motorway rule (the test zones have no motorway)
- Motorways are excluded unless tagged `motorcycle=yes`, which may exclude stretches two-wheelers can legally use. Check by hand before any zone near one.
- The golden routes need a real OSRM, so CI does not run them yet (next Issue).
- OSRM prints node ids as doubles with 10 significant digits. The signal check matches at that precision (which can only make it stricter), and the closed-street check uses exact ids under 1e10.
