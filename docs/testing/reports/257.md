# Test report: a second Firebase key for the customer app's own project (#257)

## Why
The customer app's package `com.ninzo.ninzo` was deleted from the **Ninzo Rider** Firebase project, and Firebase keeps a deleted app's package for 30 days with no restore in the console. The owner chose to put the customer app in its own project, **Ninzo Customer**. A device token works only through the project its app is registered in, so the backend needs one key per project.

## What changed
- `fcm.FromEnvKey(getenv, name)` reads a named variable; `FromEnv` uses `FCM_SERVICE_ACCOUNT_JSON`, as before.
- customer-api also reads `FCM_CUSTOMER_SERVICE_ACCOUNT_JSON` (optional). Set but unusable stops the API from starting, as #252 does.
- `orders.TopicPusher` sends each push topic through its own pusher, with the log stand-in as the fallback.
- `pushersFor` in `apps/customer-api/push.go` routes:
  - `push.rider` through `FCM_SERVICE_ACCOUNT_JSON`;
  - `push.customer` through `FCM_CUSTOMER_SERVICE_ACCOUNT_JSON` when it is set, else through the same project as riders, as before;
  - a topic with no project is logged only.
- No contract change. `env.example` lists the new name with no value.
