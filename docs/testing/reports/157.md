# Test report: #157, the rider app's new operations (contract and mock)

Date: 2026-11-11. Contract and mock only; the server side is #159. No migration.

## What was added (design on #157, from the rider app developer's feedback #154 and the owner's answers)
Rider contract: updateRider (name, preferred area), listRiderNotifications, listRiderShifts (with online and break time), getShiftSummary, startBreak and endBreak (a console setting for the longest break), cancelRestock (a confirmed request before the hub accepts), markWaitingAtGate (the customer is told), submitStockCount (a hand count), an optional device_id and take_over on startShift (the other-phone check, and taking a shift over after a reinstall), and new fields: Rider.preferred_area, Shift break times and device_id, RiderOrder.waiting_since, VerificationResponse.documents (reasons per document). Customer contract: rider_waiting_since on the order. The new writes are direct only (not in the offline batch); each raises seq, so the app refetches state as for any change.

## The first CI run
The database check failed: the contract added required fields to replies the server already sends (Shift break times and device_id, RiderOrder.waiting_since, the customer's rider_waiting_since, Rider.preferred_area, VerificationResponse.documents), and the server did not send them. The server now sends them as null (documents as an empty list) until #159 builds them; `go test -p 1 ./internal/profile/ ./internal/shifts/ ./internal/orders/` then passed locally.

## Independent review
4 FAILs, all fixed: waiting at the gate could not be used with no signal, and had no errors for an order no longer the rider's (now allowed once arrived or once the code was released after a lost signal, with the handover errors); its data map row did not raise the rider's seq; a reinstalled phone was locked out of its own shift (now take_over, and unknown_device for a device the rider never registered); a break with an open offer was undefined (now offer_open). Notes taken: the direct-only list and the seq note in contracts/README.md; the rules for the hand count, cancelling each restock state, an open shift's summary, character counting, notification privacy, and from after to.

Result: PASS
