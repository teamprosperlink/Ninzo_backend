## 1. Scope
- **n counts non-test scooters only.** `suggestIn` now reads `scooters.is_test` per free rider. With the setting on, the plan is looked up by the number of free riders on non-test scooters, and `suggestByPlan` sees only those riders, as waiting and as askable. Plans are built for non-test scooters (`placementplan.Build`), so before this a test scooter on shift made the n wrong and the plan was usually skipped.
- **Forecast in `orders_waiting`.** Migration 0057 adds `placement_plans.node_orders`, one entry per entry of `node_ids`. `Build` forecasts paid orders per cell with the same decayed weekly forecast it uses for asks (`demand.Count.Paid`), and gives each cell's forecast to the first pick, in pick order, that covers it. Plans for fewer scooters are prefixes, so the split is the same for every n. A plan move stores the rounded sum for its target node as `orders_waiting`. Older builds (null) report the node's recent orders, as before.
- **Unchanged:** today's rule, line by line (it passes `to.demand`, as before); the suggestion row, TTL, bump, push, rest time and one move per short node; the rider contract (`orders_waiting` is already "Orders expected near the node").
