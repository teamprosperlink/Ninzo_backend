## 5. Findings
- **PostGIS version differs.** Supabase has 3.3.7, and local and CI have 3.5. A test can pass locally using a function Supabase lacks. Check PostGIS functions against 3.3 when the `geo` tables are built in `v0.3.0`.
- **`supabase_admin` default grants remain.** They still give API roles access to objects made by `supabase_admin`. Our migrations run as `postgres`, so they do not apply to our tables. Only Supabase can change them.
- **Services and migrations would share the `postgres` role**, which can change the schema and turn off Row Level Security. Decide on a separate service role before the first service connects.
- **Data API setting not changed.** There is no tool for it here. API roles have no access either way, which meets decision 0005.
