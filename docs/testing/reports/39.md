# Test report: rate limits (#39)

- Date: 2026-11-06
- Branch: `feat/39-rate-limits`
- Reviewer: independent Claude subagent

## 1. Scope
Limits per network address, per phone and address, per refresh token and per session, counted in memory behind one interface. Decision 0010. Purging old rows is split to #56.

**Not covered:** whether Railway overwrites `X-Real-IP`, which must be tested on staging. The startup refusal without `CLIENT_IP_HEADER` is covered by a unit test only, because a real run stopped at an earlier check.

## 3. Scenario results
| Rule | Tested |
|---|---|
| A limit holds, and its wait is true. Refused requests do not extend the wait | Yes |
| Keys and rules count apart. Old keys go. A full table stays bounded, and still limits | Yes |
| A burst cannot slip past the limit | Yes |
| The caller's address: forged lists and repeated headers, IPv6 blocks, junk | Yes |
| Every route has its rules, checked route by route | Yes |
| A limited request does not reach the database | Yes |
| Many sessions from one address share the code limit | Yes |
| A stranger cannot lock out a phone's owner, and the phone's overall limit holds across addresses | Yes |
| Only a code really made uses up the 5: not an outage, nor a tap inside the 30 seconds | Yes |
| One refresh token repeated in a loop is limited | Yes |
| A broken limiter does not stop sign-in | Yes |
| Logs hold no number or address, and a misnamed header is warned about once | Yes |

**Deliberate breaks:** 27 on the first commit, all caught after two weak tests were strengthened. The review fixes had their own breaks.

**Existing tests changed:** none. `otpPerHour` went from 5 to 20, and those tests read the constant. The limiter's own tests were rewritten within this branch.
