# Test report: profile and devices (#58)

- Date: 2026-11-06
- Branch: `feat/58-profile-devices`
- Reviewer: independent Claude subagent

## 1. Scope
`getMe`, `updateMe`, `registerDevice`, `removeDevice`, `getRider`, `registerRiderDevice`, `removeRiderDevice`, and an optional contact-only customer email (owner). A change of sign-in method now removes every device.

**Not covered:** sending notifications, which needs the worker. Migration 0011 is not applied to Supabase. Riders have no profile edit endpoint yet.

## 3. Scenario results
| Rule | Tested |
|---|---|
| Replies carry every field the contract requires, on both APIs | Yes |
| A customer's token fails on the rider API, and the reverse | Yes |
| Blocked people are refused, and a removed profile gets 401 | Yes |
| A suspended rider can read their status, and cannot add a device | Yes |
| Name and email change alone, the email clears with null, and bad values are refused | Yes |
| Names: control, bidi and invisible-only are refused, and Indian scripts with joiners work | Yes |
| The audit log says which fields changed, never their values | Yes |
| Retrying returns the stored reply, and keys belong to one user | Yes |
| An ended session cannot read a profile, change it, or add a device | Yes |
| Devices update, move to the newest owner, are bounded at 10, and only their owner can remove them | Yes |
| A device can be removed after sign-out | Yes |
| A change of sign-in method removes every device | Yes |

**Deliberate breaks:** 25, with 24 caught. The other, skipping the stored reply, is also covered by the idempotency fallback. Review fixes had their own breaks.
