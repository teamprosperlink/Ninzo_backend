# Test report: placement plans per zone, weekday and half-hour (#224)

- Date: 2026-11-13
- Branch: `feat/224-plans`
- Environment: Windows 11 (arm64), Go 1.27.3, geo Postgres on 5433

## 1. Scope
- **Migration 0053:**
  - `placement_builds` and `placement_plans`, both append-only through `forbid_change` triggers.
  - Global settings `placement_busy_share_pct` (30) and `placement_weeks` (4), cleared from zone override rows as in 0049.
- **`internal/placement`:**
  - `GreedyCaps` gives each candidate its own capacity, and `Plan.Picks` records the pick order.
  - `Score` gives the expected and covered shares for any set of picks.
  - `Greedy` now wraps `GreedyCaps`.
- **`internal/placementplan`:**
  - `Build`: candidates are the zone's non-test staging nodes with their capacities. Demand is the Asked count over the last `placement_weeks` weeks, only for cells whose centre lies in the zone. The forecast is v1 with decay 0.8, and coverage is within `sweet_spot_budget_s` by road. Plans run for n = 1 … min(active non-test scooters, total node capacity). Each n's plan is a prefix of the greedy order.
  - `Latest` reads the plan for a moment and an n.
  - A build with no nodes, no scooters, no demand, or straight-line roads is refused, and nothing is stored.
- **`cmd/placement -zone <id> [-osrm] [-remote]`:** local only by default; `-remote` (Supabase) needs the owner's okay.

  - the latest build wins
  - plans are append-only
  - refused without what a build needs, with nothing stored
  - the window is `placement_weeks` long: the stored window, and only demand inside it counts

  - `TestGreedyCapsRespectsEachCapacity`
  - `TestFewerScootersArePrefixPlans` (30 random cases)
  - the existing tests are unchanged and pass

Following the precedent for `road_data_versions` and `gate_cells` (written by commands), the two plan tables were added to that test's documented "not yet used" list, with the writer and next reader named. That is a test edit, and it is disclosed here and in the PR. Relocation v2 will take them off it.

## 3. Deliberate breaks
Each break was made alone and caught, then the code restored (checked with `cmp`).

| Break | Caught by |
|---|---|
| Test nodes used | `TestABuildPlansOnlyWhereAndWhenDemandIs` |
| Cells outside the zone counted | same |
| n not capped by scooters | same |
| Oldest build read | `TestTheLatestBuildWins` |
| Wrong node per pick | `TestABuildPlansOnlyWhereAndWhenDemandIs` |
| Demand window one week short | `no demand recorded in the zone in the window` |
| Demand window one week long | `window 2026-10-09 to 2026-11-12, want 2026-10-16 to 2026-11-12` |

The short-window break was **not caught at first**: no test had demand exactly `placement_weeks` back. `TestTheWindowIsPlacementWeeksLong` was added.
