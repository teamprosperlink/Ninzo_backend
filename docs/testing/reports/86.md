# Test report: GPS pings, the zone timer and handover (#86)

- Date: 2026-11-09

## Scope
v0.5.0 part 2. `locationPing` (kept in `location_pings`, its own rate limit), the zone timer from GPS, arrival, the missed timer, `rider_moving` on Ready, `handOver` with the customer's code and quantities, stock taken off for good, and the signal-lost release of the code. Migration 0020.

**Not covered here:** live streams (part 3), remedies and support alerts, the offline event batch, reassignment after no ping (v0.6.0), the in-zone shorter wait, and daily ping partitions.

## Scenarios
| Rule | Tested |
|---|---|
| One ping inside the zone starts nothing; two in a row start the timer once packed and past the minimum wait, with `seq` moving | Yes |
| One ping inside the perimeter stops nothing; two stop the timer; the code shows to the customer at arrival, and the rider sees `otp_available` | Yes |
| A packed rider already inside the perimeter gets no timer | Yes |
| Pings before packing start nothing | Yes |
| The minimum wait holds the timer | Yes |
| The timer is marked missed once its length passes, with `seq` moving once | Yes |
| Late, inaccurate, repeated and jumping pings are kept as evidence only; pings never change; a flush of old pings never starts a timer; zone counts must be in a row | Yes |
| Ready is refused with `rider_moving` on a fresh moving ping | Yes |
| Handover: wrong code, 5 wrong codes lock it, before packing, another rider, bad quantities, more than ordered, far from the gate, partial, a repeat after success | Yes |
| After handover: stock leaves the scooter for good with the ledger, the code is cleared, the rider is free, the customer sees `handed_over` | Yes |
| A handover with no GPS records arrival from the handover, and is flagged | Yes |
| The code is released when the signal is lost after the timer, and not while the rider keeps pinging | Yes |
| A ping with no order is kept; bad pings are refused | Yes |

**Deliberate breaks:** 27, all caught after four tests were added and one invalid break was redone.

**Bugs found while testing:** a repeated device time was not seen as a repeat, because the database keeps microseconds; and the handed quantities were changed in place before being saved. Both fixed.

**An existing test changed:** `TestSchemaMatchesTheDataMap` now also expects `location_pings`.
