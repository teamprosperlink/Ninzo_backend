## 3. Scenario results
- 2165 responses validated against the contracts, across every operation and scenario.
- 558 orders checked against the stage table, from GET and from streams at three speeds.
- Every action is checked against the same scenario's order: cancel, gate change and call.
- GET and stream agree on stage and seq for every scenario, and timer values never change.
- 12 deliberately wrong orders must fail the stage check.

## 4. Manual / end-to-end validation
The real binary was started, and Schemathesis ran against it. Generated Dart names were clean on an earlier build, and were inspected but not compiled.

**Limits of this evidence:**
- `content_type_conformance` is left out, and fuzzing sends valid requests only, because Go's HTTP server answers malformed header names in plain text before any handler runs. Coverage still sends invalid requests.
- The Bruno collection was not opened in Bruno. A test confirms the mock accepts its bodies.
- `deploy/Dockerfile.service` was not built. That comes with #9.
- This mock does not prove the real backend. It only gives app developers something true to the contract.

## 6. Defects found
Fixed before merge.

| ID | Description |
|---|---|
| D1 | GET and streams built their data separately and disagreed, so an app could ignore every stream update. Rebuilt on one story per scenario |
| D2 | Renewing a token closed the connection, and a missing auth frame gave no 4401 |
| D3 | Cancel, refund and other actions ignored the order's stage and reason |
| D4 | Request bodies were unbounded, and were stored whole |
| D5 | Stage tests passed on wrong data |
| D6 | Reconnecting after a drop could never succeed |
| D7 | An invalid date was echoed back. The rider handover contract lacked its 503. The webhook signature was any string |

## 7. Verdict
PASS for this phase.
