# Test report: console order search and timeline, the server side (#146)

Date: 2026-11-12. Local Postgres only. Migration 0041 is not on Supabase. Independent review: not yet done (to be run before the PR).

## What was built
- `internal/console/orders.go`: `listAdminOrders` and `getOrderTimeline`, mounted by `MountOrders` in `apps/console-api/main.go`. Permission `orders.read` (already in `perms.go`; 403 names it). Reads are not audited, as for the audit log and review queue.
- `q` is an order number (letter and four digits, any case; looked up by the unique `order_no` index through every number that prints the same, since the form repeats every 260000 orders), an order id, or four phone digits (customers and riders found by `right(phone, 4)`, then their orders). Anything else, or a bad `state`, `zone_id`, `from`, `to`, cursor or limit, is 400 `invalid_request`. An empty `q` means no filter. Paging uses the console's `(created_at, id)` cursor, newest first.
- The timeline merges `order_events`, `offers`, `payments`, `refunds`, `remedies`, `problem_reports`, `support_tickets` with their message senders, `arrival_reviews` and the order's and its refunds' `audit_events`, oldest first, in one repeatable-read read-only snapshot. Equal times fall in the contract's source order. Pings are counted (`count`, `first_at`, `last_at` by `received_at`), never listed.
- Privacy: only `right(phone, 4)` is read; the gate is its label and pin; ticket text, problem notes, audit before/after, entry notes and the handover code are not read into the reply.
- Migration 0041: `orders_created_idx`, `orders_zone_created_idx`, `orders_rider_created_idx`, `people_phone_last4_idx`, and by-order indexes on `offers`, `support_tickets`, `arrival_reviews`, `refunds`. No table or column change.
- `internal/console/console_test.go`: one line added to the fixture's router (`MountOrders`). No test was edited or removed. No exact field list in the contract tests grew.

## Independent review
A separate reviewer found three moderate problems and four lower-risk points.

Fixed:
- **Staff-typed text reached the timeline.** The audit reason, such as an arrival review's note, could hold a phone number or address. Audit events now pass on only the action and the entity. The test plants a phone number in the audit reason and checks that it never appears.
- **An arrival-review decision looked like a second state change.** An order event with the same from and to state now shows as `order.noted`, not `order.<state>` again.
- **An order whose customer has no phone would fail with 500.** The last four digits are now `coalesce(..., '')`. Today no order can exist without a phone; this guards against later removal of phone numbers.

Breaks on the fixes: putting the audit reason back failed the test, and so did treating same-state events as state changes. Both were restored.

Kept, and recorded in known downsides:
- An empty `q` is read as "no search", although the contract sets minLength 1. Clients built from the contract never send it.
- The catch-all WHERE may use a generic plan, so it may not use the search indexes.
- `ticket.resolved`, `payment.*` and `refund.*` take their time from `updated_at`.

After the fixes: the `Order|Search|Timeline` tests pass; the full suites are listed in the PR.
