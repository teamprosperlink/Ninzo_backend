# Test report: demand per cell and half-hour, and forecast v1 (#220)

- Date: 2026-11-13
- Branch: `feat/220-demand`
- Environment: Windows 11 (arm64), Go 1.27.3, geo Postgres on 5433

## 1. Scope
- **Migration 0052:**
  - `demand_checks` (day, band, cell, who, outcome). Its primary key deduplicates, and RLS is on.
  - The global setting `demand_retention_days`, default 84 (7–365). It is cleared from zone override rows, as in 0049 and 0051.
- **`internal/demand`:**
  - `Record` saves one check.
  - `Counts`: asked, offered and refused (distinct customers), plus paid orders at the gate's cell. A redacted gate is not counted.
  - `Forget` (erasure) and `Prune`. `Pruner` runs at most once an hour.
  - `History.Forecast` and `History.Backtest`.
- **`availability.Service.get`** records each real answer, best effort: a failure is logged and the customer still gets their answer.

## 3. Deliberate breaks
Each break was made alone and caught, then the code restored (checked with `cmp`).

| Break | Caught by |
|---|---|
| Hash not salted by day | `the hash must differ by day and customer, and be 32 bytes` |
| Forget only today | `forgot 1` |
| Prune `<=` (one day too many) | `pruned 3` |
| Redacted gates counted | `Counts` (Paid 3) |
| zone_off counted as asked | `Asked:4` |
| A record failure fails the request | `a failed record failed the request: 500` |
| Forget limited to recent days (the first version's behaviour) | `forgot 4` (a 200-day-old row left behind) |

The last break was **not caught at first**. The test revoked INSERT as `ninzo_service`, which does not own the table, so the revoke did nothing. The test now renames the table as its owner, and the break is caught.

## 4. Independent review
- **First pass: FAIL**, with two must-fix items. Both are fixed:
  - **Forget only covered the retention window.** Rows that a late prune left behind, or that a cut in retention left, were missed. Forget now hashes for every day the table holds and deletes by (day, who), which uses the primary key. The test adds a 200-day-old row.
  - **The privacy claim was overstated.** A date salt only hides customers from someone holding the table alone; anyone with database access can recompute it. That is now stated plainly in the migration and known_downsides, and an HMAC keyed by a server secret is recorded as the open option.
- **Minor items, fixed:**
  - Backtest scores only pairs where the forecast or the actual is not zero, so a longer window cannot lower the error by adding quiet cells.
  - Forecast normalises the day to IST midnight, with a test.
  - Recording and pruning run under a 2 s timeout.
  - Counts documents that Offered + Refused can exceed Asked.
  - The test for "the id is never stored", which could not fail, now checks that the stored value is the day's hash.
- **Second pass: PASS.** Every fix was checked. Six mutations were each caught: Forget hashing only today, Forget limited to 84 days, Forget deleting by day only, no IST normalisation, no zero/zero skip in Backtest, and a raw id stored. Notes:
  - A slow database can add up to 2 s to the answer.
  - A row written between Forget's SELECT and DELETE is missed. That is unlikely during an erasure.

The 2 s timeout on recording is not tested; it bounds a slow database, which the tests do not simulate.
