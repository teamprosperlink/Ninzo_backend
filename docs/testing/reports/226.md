## 1. Scope
- **Migration 0054:** the global setting `relocation_by_plan` (0 or 1, default 0), cleared from zone override rows.
- **`relocation.suggestIn`:** with the setting on and a plan for this weekday, half-hour and free-rider count, `suggestByPlan` chooses the nodes.
  - A node is **short** when the plan wants more riders there than are waiting; the largest shortfall goes first.
  - The **donor** is the nearest node with more riders waiting than the plan wants.
  - With no plan for the moment, or with the setting off, today's rule runs.
- **The insert is shared** between both rules (`suggest`). It is the same row, TTL, rider_state bump and push, so the flow is the same:
  - a suggestion only
  - one move per short node per check
  - none toward a node with a move in play
  - the rest time
  - accept, arrival, pay
- **New reason text** for plan moves: "More orders are expected here soon". `reason` is free text in the rider contract, so the contract is unchanged.
- **Data map:** `suggest_relocations` reads the plan tables. They come off the data-map test's not-yet-used list (added in #224).
- **CI:** the database job now runs `./internal/relocation/`, which the Taskfile already ran.

## 3. Deliberate breaks
Each break was made alone and caught, then the code restored (checked with `cmp`).

| Break | Caught by |
|---|---|
| Plan used with the setting off | `TestByPlanOffIsTodaysRule` |
| No fallback to today's rule | `TestNoPlanForNowFallsBackToTodaysRule` |
| A donor at its plan target asked (`<` for `<=`) | `the donor must be the node with a surplus` |
| A node with a move in play counted short | `TestAMoveFollowsThePlan` (a second move) |

The donor break was **not caught at first**: in the first version of the test, the surplus node was also the nearest. The test now puts the node at its target nearer.
