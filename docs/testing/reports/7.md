## 6. Defects found
All were found in review, and fixed before commit.

| ID | Description |
|---|---|
| D1 | The offline OTP hash was cracked in under a second, allowing a faked delivery. Removed: only the server checks an OTP |
| D2 | A rider with no signal at the gate deadlocked: no arrival, so no OTP for the customer |
| D3 | Offline event results, payloads and conflicts were undefined |
| D4 | Direct and queued handovers could disagree |
| D5 | Ready was unreachable after an app restart, and stale tokens had no error |
| D6 | A rematched rider could read another rider's progress |
| D7 | Nodes, manual restock and hub shortfalls could not be rendered |
| D8 | The signal-lost OTP rule let a late rider with working GPS get the OTP by phone |
| D9 | A valid offline handover could be rejected after the rider rode off |

## 7. Verdict
PASS for this phase. Not usable by the app developers until the mock server (#8) exists.
