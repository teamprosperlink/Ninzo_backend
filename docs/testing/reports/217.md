# Test report: tiny negative numbers from OSRM count as 0 (#217)

- Date: 2026-11-13
- Branch: `fix/217-negative-distance`
- Environment: Windows 11 (arm64), Go 1.27.3, OSRM v6.0.0 (`scooter-2`) on the test-zone extract at localhost:5001

## Found
While testing placement (#216), OSRM answered `/table` with distance `-0.2` and duration `0` for a source on the destination (14th Cross Road, 12.976663, 77.635384). `goodNumber` refused any negative, so the whole table counted as an OSRM failure and fell back to straight lines. Live matching with `matching_by_road` on would have done the same whenever a rider stood on the gate.

## Change
`goodNumber` accepts a value above -1 (one second or one metre) and sets it to 0. A value at or below -1 is still a bad reply. Every reply number, in route, table, nearest and via, goes through it.
