## Scenarios
| Rule | Tested |
|---|---|
| Customer stream: `auth_ok`, heartbeat with `seq`, `order_update` with the same order GET returns, nothing on a hidden change, `rider_accepted` once shown, `rider_position` with no `seq`, a last update then 4410 when the order ends, 4410 at once on an ended order | Yes |
| Rider stream: `offer` when an offer goes out, `order_state` after accepting, never the handover code | Yes |
| Refused: no auth frame, a bad token, the other app's token, another customer's order (4403), no such order (4404), an ended session (4401) | Yes |
| A token not renewed closes with 4401; a renewal for someone else closes the stream | Yes |
| The rider's position stays hidden during the minimum wait | Yes |

**Deliberate breaks:** 15. 14 caught after one test was added and three invalid breaks were redone. Accepting a bad token in the first frame was not caught by its own check, because the session check after it still closes with 4401.

**A bug found while testing:** a rider with no saved `seq` reads as 1, so the stream missed the first change. The stream now compares the raw value.
