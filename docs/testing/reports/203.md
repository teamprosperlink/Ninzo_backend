## 1. Scope
- **`gatecells.GeoJSON(grid, tiers)`** writes a FeatureCollection with one closed hexagon per cell, in lng,lat order. Each cell's properties are `cell`, `reach`, `in_timer_zone` and `road_seconds` (null when unreachable). The collection carries `build_id`, `road_data_version_id`, the grid, and the budgets used (now with JSON names).
- **`cmd/gatecells -local|-remote export -gate-history <id>`** writes only the GeoJSON to stdout; the target line goes to stderr. It uses the zone's settings in force, needs no OSRM, and refuses an erased gate version.

What they check:
- Every feature is a closed seven-point ring in lng,lat order, inside Bengaluru.
- Each polygon's mean point falls in the cell it is labelled with.
- The properties equal `Classify`'s answer, and `road_seconds` is null exactly when the cell is unreachable.
- The command's stdout parses as JSON with more than 400 features and the zone's budgets.
- Export with no build fails, and so does export of an erased gate version.
- Export's argument rules hold.

The existing command tests still pass with the new argument rules.

## 3. Deliberate breaks
Each break was made alone, the tests run, then the code restored (checked with `cmp`).

| Break | Caught by |
|---|---|
| lat,lng order | `feature 0: [12.936... 77.615...] is not lng,lat in Bengaluru` |
| Ring not closed | `feature 0: not a closed hexagon` |
| Target line on stdout | `stdout is not only GeoJSON: invalid character 'a' ...` |
| Ring reversed (clockwise) | `feature 0: ring is clockwise (signed area -2.49e-06)` |

## 4. Independent review
PASS. Its three test gaps are closed: the rings are checked to be counter-clockwise (RFC 7946), with a break that was caught; export's argument rules now sit in the database-free `TestBadArgumentsTouchNothing`; and `build` without `-road-data` is covered.

## 5. Known limits
The export is for the owner and ops: the cells give a gate's location away. Write it under `tools/osrm/data/` (git-ignored) and never share it outside the team.
