## Independent review
A separate reviewer read the change against the contract. It found two bugs and six lower-severity points.

Fixed:
- **A break could start while the matcher was offering the rider an order** (READ COMMITTED, with no lock on the matcher's side). `freeRider` now locks the shift row (`FOR UPDATE OF sh`), as `startBreak` does. Test: `TestABreakWaitsForAMatcherLookingAtTheRider`.
- **The customer's seq could stay put after a wait-at-gate push** while the timer was running inside the minimum wait. The seq rise and the push now use the same stage test as the customer's view. Test: `TestWaitingWhileTheTimerRunsRaisesTheCustomerSeq`.
- **Ending a shift mixed the app clock and the database clock**, so ending soon after a break started could return 500. The break now closes at `greatest(now(), started_at)`. Test: `TestEndingTheShiftClosesABreakStampedAheadOfTheDatabaseClock`.
- **No indexes for shift history and summary.** Added `shifts (rider_id, started_at DESC, id DESC)` and a partial index on `orders (rider_id, handed_over_at)`.

Left as known downsides or follow-ups:
- A held order goes to NO_SCOOTER when its rider starts a break. This is dispatch code, owned by the geo session (#170).
- Existing zone rows keep `max_break_s = 1800`, as in 0034.
- A shift's device can later move to another rider if the phone is re-registered.
- A break past its end time runs until the next 5-second pass.

Breaks on the fixes: each of the three fixes was undone in turn, and its new test failed each time (lock removed, no seq rise, the database clock at shift end). Each was then restored.

After the review fixes, every touched package was run again one at a time with `go test -p 1 -count=1`: orders ok (985 s), availability, restock, profile, notify, relocation, geo, console, tests/contracts and internal/mockserver all ok; shifts (237 s) and tests/db (122 s) ok.
