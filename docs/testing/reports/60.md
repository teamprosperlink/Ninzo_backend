## 2. What went wrong, and what fixed it
1. The first `DATABASE_URL` used the `postgres` login. The API refused to start, as designed, and the owner changed it to `ninzo_service`.
2. Then both APIs timed out reaching the database. A temporary service on Railway showed the network was fine, and that the same connection worked, but that the first 2-second database check could time out from the US. A redeploy with the current settings worked. The check is now 8 seconds (#61). Stale settings were probably part of the cause. That is not confirmed.
3. In the US region, each request took 3 to 4 seconds, because the database is in Mumbai. Moving both APIs to Singapore made them about 4 times faster.
