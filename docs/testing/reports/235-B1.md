## 1. Scope
Part B1 of Issue 235. The real rider API (apps/rider-api) now returns what `contracts/rider/openapi.yaml` says, for these items only:

1. Rider: `phone` (the rider's own), `email`, `area`. updateRider takes `email` and `area`; `area.name` and `preferred_area` stay the same text.
2. Shift: `online_at`, `planned_end_at`, `break`, beside `break_started_at` and `break_ends_at`. startShift keeps `checklist`.
3. Shift list: `days`, and `online_at`, `planned_end_at`, `orders`, `portions`, `avg_delivery_s` on each entry.
4. Offer and RiderOrder: `total` and `payment_method: "prepaid"` everywhere. Both are now required in the contract.
5. Restock hubs: `manager_phone`.
6. `takeBreak` (a length the rider picks, capped by `max_break_s`) and the `endBreak` alias path.
7. Rider `requestOtp`: 400 `invalid_phone` for a bad number. Customer and partner sign-in unchanged.

Migration `0055_rider_apk_fields.sql` (Up and Down, `LOCK TABLE hubs, riders, shifts` first, in a fixed order): `riders.email`, `area_name`, `area_city`, `area_lat`, `area_lng`, `hubs.manager_phone`, `shifts.online_at`, `planned_end_at`, `checklist`.

Not in B1: `goOnline`, `setPlannedEnd` (B2). The columns exist and are read, but nothing sets them yet.

## 2. Decisions made while building
- **Phone** is read from `people` through `riders.person_id`: the rider's own number only. If an account has none, the key is left out (the contract's `phone` is never null).
- **Area and preferred_area** are kept the same text, in the code and in the database (`riders_area_follows_preferred`, `riders_area_together`, `riders_area_valid`). `preferred_area` alone with other text drops the stored place. `area: null` clears the place and the name it gave `preferred_area`.
- **Audit** of updateRider holds `has_email` and `has_area`, never the email.
- **Break:** `takeBreak` runs the same handler as `startBreak`. The break ends at start plus the shorter of the length asked and `max_break_s`. A rider already on a break gets it extended (never shortened, and nothing changes or is audited if it is not longer). The break time is cut to whole microseconds so the reply is what the database holds.
- **Break object** is built from `break_started_at` and `break_ends_at` in one place (`shift.MarshalJSON`, and the open shift of the state), so the two forms cannot disagree.
- **Checklist:** more than 20, an empty code, a repeated one, or a non-text item is 400. A code of another shape than `[a-z0-9_]{1,40}` is ignored (it cannot be one of the settings' codes). Codes are not checked against the settings yet because `getRiderSettings` is part B2.
- **`days`:** the last N days in India time, today included, 1 to 31, all on one page with `next_cursor: null`, not with `from` or `to`. `limit` and `cursor` are ignored with `days`. Without `days` nothing changed.
- **invalid_phone:** only when the phone is present and not an Indian mobile in E.164 form (including a non-text phone). A missing or empty phone, or a broken body, stays `invalid_request`. Customer and hub staff are untouched.
- **Console:** `hubs.manager_phone` is not in the console contract, so the console's hub create and update were left alone. The number can be set in SQL until the console takes it.
- **Privacy:** replies were checked for `"phone`, `+91`, `"customer`, `"address` in the offer and order views; the only phones sent are the rider's own and a hub's manager phone.

## 6. Defects found while building
- The first draft of `riders_area_follows_preferred` let an area with no `preferred_area` through (a CHECK passes on NULL). Found by the new database test, fixed in the migration before any release.
- The break reply carried nanoseconds while the database keeps microseconds, so a later extension did not equal the first reply. Fixed by cutting the time to microseconds, found by the extension test.
- `length_s` given as text (`"600"`) was accepted by a number decoder. Fixed to refuse it, found by the new test.

## 7. Open points for the reviewer

- The console cannot set `hubs.manager_phone` (no field in the console contract).
- Checklist codes are not checked against the settings list until B2 builds `getRiderSettings`.
