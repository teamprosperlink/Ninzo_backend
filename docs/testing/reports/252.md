## 1. Scope
- **`internal/fcm.Sender`** implements `orders.Pusher`, so `Deliver` and `LogPusher` are unchanged.
  - **Auth:** an RS256 JWT from the service account, swapped at `token_uri` for an access token. The token is cached until a minute before it expires, and dropped after a 401.
  - **Message:** FCM v1 `messages:send`. `notification` carries a fixed title and body by topic and stage or kind; they name nobody, and an unknown kind gets "Ninzo / You have an update". `data` carries the outbox payload as strings, plus `topic`.
  - **Priority and expiry:** a rider `offer` (1 minute), and the customer `timer_running`, `arrived` and `rider_waiting` (5 minutes), go as Android `high` with that `ttl`, and on iOS as `apns-priority` 10, `interruption-level: time-sensitive` (shown so only with the app's capability) and `apns-expiration`. Other order pushes go normal (priority 5) and expire after an hour; the rest use FCM's default.
  - **Replacement:** `order:<id>` when the push names an order, `topic:kind` otherwise, as Android `collapse_key` and `notification.tag` (the tag replaces a shown notification) and `apns-collapse-id`. Keys over 64 bytes are hashed.
  - **Errors:** only FCM's UNREGISTERED deletes the row in `devices`; a bare 404 (a wrong project or address) is retried and keeps the token. SENDER_ID_MISMATCH and INVALID_ARGUMENT are logged (no token) and dropped, token kept. Any other failure returns an error, so the outbox retries. A refused access token reports Google's error and description. A 200 body is read through so the connection is reused.
- **Config:**
  - `FCM_SERVICE_ACCOUNT_JSON`: unset keeps `LogPusher`; set but unusable stops customer-api from starting.
  - `token_uri` must be https, or http on localhost for tests.
  - `env.example` drops `FCM_PROJECT_ID` and `FCM_SERVICE_ACCOUNT_FILE`.
- **Refund processed:** a `push.customer` with stage `refund_processed`, `order_id` and `refund_id`. It is queued in the transaction that moves the refund from pending to processed, whether by the `refund.processed` webhook or by `SendRefunds` when Razorpay answers processed. It is queued once because only one path can win the move from pending.
- **Owner steps:** `docs/planning/firebase_setup.md`, linked from the setup checklist and CLAUDE.md.

## 4. Independent review
The first review was a **FAIL**, with one blocking item, now fixed: any HTTP 404 deleted the token. A wrong project id or address would have deleted every device token on the first pass. Only UNREGISTERED deletes now. Should-fix items, all fixed:
- SENDER_ID_MISMATCH and INVALID_ARGUMENT retried forever, repeating the push to the person's other devices. They are now dropped with a log, and the token is kept.
- Customer handover pushes went at normal priority, which Doze and APNs can delay. `timer_running`, `arrived` and `rider_waiting` now go high.
- "Replaces the older one" held on iOS only. `android.notification.tag` was added.
- There was no expiry. Urgent pushes now last 1 or 5 minutes, and other order pushes an hour.

Nits taken:
