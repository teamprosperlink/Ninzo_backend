## 1. Scope
Owner decision 0009: one sign-in method per customer, with no merging. A Google customer can switch to phone at sign-in. Settings can change the method. Each method is a component, switched with `SIGNIN_METHODS`. Downsides are indexed in `docs/engineering/known_downsides.md`.

**Not covered:** the Android client. Migration 0010 is not applied to Supabase. The warning SMS is queued, but nothing delivers it yet. IP rate limiting is #39.

## 6. Known limits
See `docs/engineering/known_downsides.md`.

- **Any future block or suspend code** must take the actor lock before changing a status. Changing the row first can deadlock with removing an empty account. Postgres stops one side, and nothing is lost, but one request fails.
- **A rider profile being created at the same moment** as an empty account is removed makes the first reply a 503. The foreign key stops the removal, and nothing is lost.
