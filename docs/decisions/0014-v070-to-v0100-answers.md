# 0014: Answers for v0.7.0 to v0.10.0

- Status: Accepted
- Date: 2026-11-10
- Deciders: Owner

## Decision
The owner accepted the plan for v0.7.0 to v0.10.0 in `docs/planning/milestones.md`, and answered:

| # | Question | Answer |
|---|---|---|
| 1 | Rider earnings: pay per order, incentives, paid relocation time | Set by the admin in the console. Until then, test values that the admin changes later |
| 2 | Hubs: how many, and where | Entered by the admin in the console. Until then, test data. Nothing in the console names a fixed set of hubs |
| 3 | How hub staff sign in | Phone and OTP, for now |
| 4 | How console staff sign in | An ID and password, then a code from an authenticator app (TOTP) |
| 5 | Staff roles and approvals | Admin, ops, support and hub manager. A refund above a set amount, and a change to settings, need a second person's approval |

## Consequences
- Earning rates, hubs, the menu, prices, zones and gates are all data the admin enters. Test data stands in until the console (v0.9.0), and `real_and_stand_ins.md` says so.
- Console staff are the one role with a password. It is stored as a slow hash, never in plain text, with a lockout after repeated failures, and the TOTP secret is stored encrypted. The rules go in `authentication_rules.md` when v0.9.0 starts.
- The approval amount for refunds is a setting, so the admin can change it.
